# Search publication and Google Search Console

## Production search metadata

`uv run python scripts/build_site.py` generates the full bilingual production site and then
publishes search metadata using `src/physics_atlas/seo.py`. Run this complete build for deployment;
`zensical serve` is a documentation preview and does not run the final search publication step.
Never edit or commit generated files under `site/`.

The single sitemap is published at:

<https://d1ssk.github.io/interactive-physics-olio/sitemap.xml>

It includes the English and Japanese home pages, field indexes, articles, standalone applications,
and update history. The inventory comes from public Markdown sources and visualization metadata,
independently of the navigation configuration. Developer instructions and asset documentation are
excluded. A missing translation, missing article, or standalone/article URL collision fails the
build. Both locale URLs use trailing slashes, consistent with the canonical URLs.

Each indexable page has a page-specific title and description, its own absolute canonical URL, and
the same pair of absolute `en`/`ja` alternate links in its initial HTML head. Japanese pages remain
self-canonical; their English translation is an alternate, not a canonical replacement. Standalone
applications also have an initial localized heading and locale-specific home/counterpart links.
Their controls continue to use their existing browser locale dictionaries. English plot text and
scientific payloads are preserved.

Descriptions come from `summary`/`summary_ja` for visualizations and shared field definitions for
field indexes. Home and update-history descriptions live in the search module. Prose pages may
override their title or description using YAML front matter; new prose pages outside the existing
categories must supply a description in both language sources.

Article-embedded `/app/` pages and 404 pages have `noindex` and are excluded from the sitemap. They
remain crawlable, so Google can read that directive and discover links. Do not block those URLs or
the JavaScript, CSS, workers, or mathematical rendering assets in robots.txt.

There is no `lastmod` until a reliable significant-content update date is available. Build dates
are not content update dates. `priority` and `changefreq` are omitted. Locale sitemaps generated by
Zensical are replaced by the complete root sitemap; stale compressed versions are removed.
`hreflang` is maintained only in HTML, rather than duplicated in the sitemap.

## Register and verify the property

1. Add a **URL-prefix property** for
   `https://d1ssk.github.io/interactive-physics-olio/` in Google Search Console. This covers the
   Japanese `/ja/` subtree as well. A Domain property requires DNS verification, which this
   project does not control for `github.io`.
2. Choose an offered ownership verification method. The site already has Google Analytics
   configured, so Analytics verification may be available if the account and permissions meet
   Google's requirements. Merely including an Analytics ID does not establish ownership.
3. For HTML-tag verification, copy the issued `content` token into
   `project.extra.search_console_verification` in `zensical.toml`. The build emits
   `<meta name="google-site-verification" ...>` in the English property homepage head. No
   placeholder token is published. This is a public verification token, not an Analytics ID.
4. Deploy and check that the issued tag appears in the homepage source, then complete verification
   in Search Console. Keep the token configured afterward; Google periodically checks ownership.
5. In the Sitemaps report, submit `sitemap.xml` and check the processing result.
6. Use URL Inspection on representative English and Japanese articles and standalone applications.
   Run the live test, inspect the rendered page and resource loading, and confirm the canonical
   URL and indexing eligibility. Request indexing for representative entry pages if needed.
7. Monitor the Page indexing report after deployment. An embedded app being excluded by `noindex`
   is expected; an article or standalone application being excluded needs investigation.

## robots.txt and GitHub Pages project paths

Google reads robots.txt at the **host root**:

<https://d1ssk.github.io/robots.txt>

This repository publishes below `/interactive-physics-olio/`. A file at
`/interactive-physics-olio/robots.txt` or `/interactive-physics-olio/ja/robots.txt` cannot configure
crawling. Therefore this project does not generate a misleading project-local robots.txt.
If the host-root user site is managed separately, the following can be incorporated into its
robots.txt, retaining any rules needed by other projects on the same host:

```text
User-agent: *
Allow: /interactive-physics-olio/

Sitemap: https://d1ssk.github.io/interactive-physics-olio/sitemap.xml
```

Without a robots.txt restriction, crawling is allowed by default; adding this file is not required
to enable indexing. Search Console submission makes the sitemap discoverable without a robots.txt
entry. Check the actual host-root response and rules when diagnosing production crawl problems.

## Validation

Run focused tests with `uv run pytest tests/test_seo.py tests/test_i18n.py` and the complete
production build. Serve `site/` over loopback HTTP for local inspection. Verify the sitemap and
representative English/Japanese article and standalone HTML responses before deploying. After
deployment, check production HTTP responses, host-root robots.txt, and URL Inspection in Search
Console. Local tests do not establish Google's crawl or index state.

Before completing a change, run `uv run python scripts/check.py --all --quiet`.

Search metadata and sitemap submission help discovery and indexing but do not guarantee inclusion
or ranking in Google Search.
